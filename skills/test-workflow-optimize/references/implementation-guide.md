# 实施与扩展指南

只阅读当前改动需要的部分。目录、档位名称和报告字段是可适配的约定，不要求把目标项目改造成特定框架。

## 诊断与最小试点

检查测试入口是否隐含环境变量、筛选、失败重跑或工作目录要求；检查根级公共配置是否在导入阶段连接数据库、加载应用，或者对每个用例自动重建全部数据。

利用已有日志或短采样分别记录 collection/setup/call/teardown。选择少量已有纯规则文件作为试点，并核对 import 链和 fixture 链。不要因一个测试没写 DB 参数就认为它不连接数据库。

改造公共配置时保持已有 fixture 名称和 helper 导入兼容。尤其注意把非 package 的测试目录改为 package 会改变模块名和历史 sibling import；不为目录整齐制造整套收集失败。新增 helper 放入支持目录，旧 helper 随改动迁移。

## 分层与档位

| 档位 | 覆盖及资源 | 典型用途 |
| --- | --- | --- |
| quick | 审核后的纯规则/合同/工具；无外部依赖 | 每次局部修改 |
| affected | 变动依赖与明确兜底，计划可只读预览 | 开发反馈 |
| integration | 真实 API/DB；通常也含跨连接语义 | 接口和持久化改动 |
| concurrency | 独立连接、CAS、锁和提交可见性 | 并发/隔离改动 |
| worker / ui | 执行工具替身；构建及前端单测 | 对应模块改动 |
| full / release | 所有约定测试；release 加构建/lint 等项目检查 | 最终验收 |

这些档位可以重叠。按项目规模选择需要的档位，不空造目录。纯测试名单或 marker 需要审核；标记本身不使测试获得独立性。数据库不可用时快速档仍应运行，必要时通过禁用同步/异步连接入口证明边界。

## 受影响计划

变动集合包括相对于明确基线的分支提交，以及 staged、unstaged、untracked、deleted/renamed。输出基线、变动文件、选中测试和选择原因。

反向依赖应处理目标语言的实际模块路径、相对导入、支持构造器和旧测试 helper。配置、权限、迁移、全局 fixture、运行时材料和工具链变更由显式规则扩大覆盖。

没有找到测试依赖不能自动解释为“不需要测试”；可能是动态加载或缺少覆盖，应扩大并说明。`no_tests` 只在可解释的范围内使用，并与通过结果区分。

## Fixture 和隔离

把可复用的不可变引导数据与每测试可变业务数据分开。可以重用前者的准备步骤或模板，但验证初始状态等价，不让可变对象跨测试共享。使用条件或事件等待代替无条件 sleep。

事务回滚优化是可选模式。建立真实连接语义分类或排除名单，记录原因与覆盖出口；不要机械沿用其他项目的名单。新增测试涉及独立事务或提交时同步更新分类。

每 worker 的数据库、临时目录、输出文件、端口和外部替身需要独立命名。不能在收集阶段全局替换 UUID/时间函数来稳定并行；为参数指定稳定 ID，保留运行时真实随机身份。

共享构造器按业务合同版本命名，返回新对象。测试读投影可以直接构造相应数据库记录，但不能据此取代独立的创建/更新 API 行为测试。

## 运行入口与资源治理

优先增强现有入口。集中组织计划、环境诊断、资源申请、命令执行和报告；本地与 CI 调用同一入口。

环境预检检查实际资源归属及关键工具的真实能力。例如媒体探针要能读取目标编码，而非只有一个可执行文件。缺失资源给出可执行的修复办法，不自动触碰生产或别的会话。

同一实验室的锁由内核锁或具备等价持有者验证的机制控制。不得因超过一个时限删除活锁。PID 与启动时间一起用于诊断，心跳是辅助证据。包装器死亡但其命令仍运行时，不立即回收资源配额。

多个 worktree 竞争同一机器时，配置合作共享预算；明确哪些旧入口尚未加入。并行上限根据 CPU、内存、IO、服务与数据库容量测量，不能只取机器核数。操作系统资源上限尽量在创建资源前预检，避免半初始化状态。

测试和整命令分别有可配置的时限，记录单位、默认值、范围和覆盖方式。给确需长时间的测试有理由的独立设置；增加时限不是修复死循环。

超时或取消保存失败阶段、节点/线程栈和进程身份，只清理本次命令的子进程。注意父进程已退出而进程组仍存在，以及平台对进程组操作的差异；用隔离的短程序验证实际取消行为。

## 结果契约

每次运行保存完整实时日志与机器可读摘要；已有 JUnit 时复用，JSON 补充缺失字段。下面是可适配字段，并非硬性 schema：

```text
run_id / schema_version / profile / base_revision
source_revision / start_fingerprint / end_fingerprint
dependency_lock / runtime_versions / resource_shape
jobs / isolation_mode / selection_reasons / fallback_reasons
queue_seconds / preflight_seconds / command_seconds
collected / selected / executed / passed / failed / errors
skipped / deselected / collection_agreement / worker_errors
exit_code / timed_out / interrupted / source_changed
failure_nodeids_and_phases / log_path / junit_path
```

空收集、执行不完整、worker 错误或源码变化都不能形成完整验收通过。前端和后端分别记录原始失败，不用修复测试运行器的名义隐藏产品失败。异常终止缺少报告文件时也要明确说明。

完整档不能偷偷继承 `-k`、skip-slow 或 collect-only；定向档允许筛选但清楚标识覆盖。失效路径/注册项应报错或诊断，不可静默降低用例数。

## 工具本身的验证

按本次实现的风险选择真实行为验证，而非只检查生成文本：

- 纯测试在数据库关闭/不可连接时仍完成，且意外连接被识别。
- 传递依赖、相对/历史 helper 导入及未知变动获得正确计划；共享配置扩大范围。
- 并行 worker 收集集合一致，参数 ID 不随运行变化。
- 活锁不能被另一个调用偷走；持有者退出后正常释放；容量遵守约定。
- 失败命令、空收集、测试超时和取消均留下非成功结果及定位证据，受控子进程结束。
- 事务优化排除项在真实连接档得到验证；新合同与旧合同分别保留断言。

这些探针在独立临时环境执行，不调用真实收费服务，也不对其他会话做杀进程试验。优先使用目标项目已有的可靠工具和测试。

## 基线、性能与交接

固定非试验条件，明确本次改变的是公共 fixture、并行数、隔离方式还是选择范围。记录两端用例集合、业务断言、代码版本、依赖、机器负载和冷热状态。对于测试基础设施重构，两端版本可以不同，但要证明覆盖与业务断言保持，不能只比总数量。

同条件重复运行用于评估噪声；不在负载明显变化或已有失败时计算可信提速倍数。排队与命令耗时分开；快速档与全量档分别报告，不能互相作速度分母。

交付项目内一份稳定指南和开发约定，回答：怎样选档、怎样新增分类/隐式依赖、怎样写版本构造器、如何看失败/超时、何时需要完整门、CI 怎样保存证据。记录实际命令、范围、失败与剩余工作；已验证范围之外不承诺结果。

迁移优先从现有瓶颈和新增测试开始，不要求一次重写全部用例。以后用真实失败和性能数据更新规则，避免把每次个案积累成对所有项目的强制条款。
