# 自动化测试效率优化

缩短日常开发获得可靠反馈的时间，同时保留完整验收的覆盖、业务语义和失败证据。适用于已有项目的渐进优化；按实际技术栈实现，不把来源项目的框架、目录、并行数或时限当成通用配置。

## 使用方式

- 用户只要求探索或总结：只读取、诊断和建议，不改项目或启动重型测试。
- 用户要求实施：遵守项目开发约定，在获准的隔离环境完成工具、试点和验证。不能把测试优化扩展成产品改版、生产部署或真实付费调用。
- 要解释原理或向团队推广，读 [设计思想](references/design-principles.md)。
- 要实现入口、选择器、数据库隔离或报告，读 [实施指南](references/implementation-guide.md) 的相关部分。

## 先形成成本与语义判断

读取项目开发约定、测试入口、配置、公共 fixture、CI、依赖锁文件及最近的真实测试日志。优先复用日志；没有必要时不为建基线立即跑几千个用例。找出已有门禁和正在使用的共享资源。

给出可核对的测试地图：哪些测试验证纯规则，哪些需要真实数据库/API，哪些验证独立连接、锁或提交，哪些涉及外部服务、浏览器或真实模型。混合文件先保留原层，不能凭名称、参数或一个 marker 判定纯逻辑。

把耗时拆成排队、环境预检、收集/导入、setup、call、teardown。区别每个用例重复付出的固定成本与少数长尾。没有数据时标明假设，再用有代表性的短运行验证。

## 优化的决策顺序

1. **减少重复固定成本。** 让纯规则测试避开应用导入、全表清理、密码哈希和角色初始化；让共享 fixture 在需要时加载。给纯测试增加连接禁用或等价检查，验证收集和执行期间都不依赖数据库。不得复用可变数据造成串扰。
2. **建立分层反馈。** 至少提供快速、完整和定向入口；按需求增加受影响、接口、跨连接、Worker、UI、发布前档。跨连接测试仍属于完整验收，不能成为优化后永久遗漏的分支。
3. **按可证明的影响选择范围。** 受影响计划覆盖分支提交、暂存、未暂存、新增和删除文件；沿依赖传播，并登记反射、运行时材料、配置等隐式依赖。不确定或共享基础变化时扩大覆盖，说明原因。纯文档变化也要核对是否为运行时输入。
4. **再增加并行。** 先隔离每 worker 的数据库、文件、端口等资源，再用实测寻找合理并行度。事务回滚优化只覆盖语义兼容的测试；独立连接可见性、CAS、提交回调、锁竞争仍使用真实连接。
5. **让失败立即可见。** 保留真实退出码、完整日志和逐阶段失败信息，记录收集、选中、实际执行、跳过、排除、超时、中断与 worker 错误。不能把零收集、只收集或部分完成写成通过。
6. **降低后续维护成本。** 版本明确的数据构造器放入 support/factories，返回新对象；新增测试不从其他测试文件借 helper。旧合同不随默认构造器静默升级，测试 ID 稳定而运行期身份保持真实。

保留现有包装器、CI 和测试语义，按瓶颈补齐；不要为统一形式替换已可靠工作的组件。先试点，再渐进迁移，避免一次搬动整个测试目录。

## 执行与质量约束

- 使用项目认可的测试入口与专属资源。数据库写入前核对真实服务器、库和归属；不能复制生产凭据或绕过门禁。不要停用其他会话正在使用的实验室。
- 完整/发布档明确覆盖合同，避免环境变量暗中注入筛选。缺失目标路径、失效名单和未约束的 worker 数应可诊断，不能静默形成绿色结果。
- 同一资源由可靠锁串行化；锁的年龄或 PID 文件不能单独证明持有者死亡。多 worktree 共用资源时考虑总预算，并说明旧入口是否参与。
- 超时或中断只清理本次拥有的子进程；保留节点、阶段和定位信息，不默认重试或靠增加超时绕过卡点。
- 不以删断言、跳过慢测试、放宽业务检查、自动 xfail、替换真实事务语义或全局篡改随机函数来制造提速。确需调整旧测试，说明产品合同依据并保留原业务覆盖。
- 新测试参数在本地 CLI/测试配置中显式定义并传递，记录单位、默认值和范围；若改到业务运行参数，另遵守项目后台配置和任务冻结约定。
- 同一次验收不要混入源码变化。记录开始/结束指纹；发生变化则标记结果不能作为稳定版本验收，不擅自撤销其他会话修改。

## 验证与交付

依据改动验证真实行为：快速档不需要数据库、影响选择不会遗漏关键变动、跨连接语义保留、并行收集一致、锁/资源预算正确，以及失败/超时/取消不能留下假成功或子进程。工具测试使用隔离的临时程序和资源，不为了验证治理去干扰其他运行。

跑本次范围必要的完整门，保留所有失败。对来源已知失败给出证据和归属；测试工具回归必须修复。连续失败应由新增证据推动诊断，没有新变化不重复启动昂贵全量。

衡量两种不同收益：同范围执行变快，以及日常选择更小且合理的范围。后一种不能冒称全量提速。性能实验固定非试验条件，允许并明确记录本次改变的因素；记录两端版本、用例集合、业务断言、依赖、资源、并行、隔离、负载和冷热状态。数据不足时只报告实际耗时。

交付项目内稳定的使用指南与简短开发约定，包含入口、分层/隐式依赖注册、fixture 扩展、结果路径和既有失败。CI 复用同一入口和报告，避免另一套选择规则。最后说明改动、实际覆盖、结果、测量边界与剩余工作。
